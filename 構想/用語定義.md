# 用語定義

本研究では、(1)分析対象である数学（線形代数）の用語、(2)研究の目的・評価に関わるメタ認知研究の用語、(3)本研究が独自に定義した仕組み・データ構造の用語、の3系統が混在する。同じ語が系統ごとに別の意味を持つ場合があるため、本書で意味を固定する。

特に紛らわしい語は「4. 紛らわしい用語の使い分け」にまとめた。

## 1. 数学ドメインの用語（分析の対象となる内容知識）

| 用語 | 定義 |
| --- | --- |
| 線形代数1 | 本研究の対象単元。教科書9章立て。この範囲の内容を概念ID体系（§3）に整理した |
| 数学的概念 | 「行列の積」「固有値」「対角化」など、教科書上の学習内容の単位。本研究ではこれを識別子付きで管理したものが「概念ID」（§3） |
| 前提概念 | ある概念を理解するために先に理解している必要がある概念。例：「行列の積」(LA-MAT-03)は「行列の定義」(LA-MAT-01)を前提とする。概念ID体系では `prerequisites` として保持し、全体が循環のないDAGであることを保証している |
| 典型的誤解 | ある概念について学習者が陥りやすい誤り。例：「(AB)^T = A^T B^T だと誤解している」。数学教育で知られる misconception にあたり、概念ID体系では `misconceptions` として保持する |

個々の数学用語（正則行列、拡大係数行列、固有多項式、直交対角化など）の定義は `手法/概念ID.md` の各概念の `definition` を参照する。本書では列挙しない。

## 2. メタ認知ドメインの用語（研究の目的・評価に関わる）

| 用語 | 定義 | 本研究での扱い |
| --- | --- | --- |
| メタ認知 | 自分の理解状態を把握し、学習を調整する能力 | 大局的な目的。ただし向上の効果検証は今回の範囲（M1〜M5）外 |
| 自己評価 | 学習者が自分の理解度を自分で評定したもの。本研究では概念ごとの「できる度」を想定 | 較正の対象。測定手法の設計は今回の範囲外 |
| 較正（calibration） | 自己評価と客観的な理解度（テスト結果）とのズレが小さいこと | 大局的に目指す状態。今回は測定しない |
| 自己調整学習（SRL） | 学習者が自ら目標設定・方略選択・振り返りを行う学習のあり方 | 先行研究 Yangら(2026) が改善対象とした能力。メタ認知と重なるが同一ではない（SRLは学習行動全体、メタ認知は自分の認知状態の把握） |
| 内省（reflection） | 学習者が自分の解答・理解を振り返ること | AIが返す「内省質問」(d) によって誘発する |
| 自己説明（self-explanation） | 学習者が「なぜそうしたか」を自分の言葉で説明すること。学習科学では理解を深める方略として知られる | 本研究では**入力データの1項目**として用いる（§3） |
| 弱点同定 | 学習者が自分の理解の弱い部分を特定すること | 可視化によって支援する対象 |
| 説明可能AI（XAI）／SHAP | 予測モデルの出力根拠を人間に提示する技術 | 先行研究が使用。本研究では使わず、LLMが直接(b)根拠を提示する |

## 3. 本研究独自の用語（仕組み・データ構造）

### 3.1 入力

| 用語 | 定義 |
| --- | --- |
| ソース | 学習者の学習データの総称（`構想/テーマ.md` での呼称） |
| 入力 | 診断の入力3点セット。**問題文**＋**学習者の解答（途中式）**＋**自己説明（「なぜそうしたか」1〜3文）** |

### 3.2 概念ID体系

| 用語 | 定義 |
| --- | --- |
| 概念ID | 1つの数学的概念に与えた識別子。`LA-<章略号>-<連番>` 形式（例：`LA-MAT-01`）。線形代数1を9章・52概念に整理した |
| 概念IDリスト／概念ID体系 | 全概念IDとその属性の集合（`手法/概念ID.md`）。プロンプトに埋め込まれ、AIはこのリスト内からのみ概念を選ぶ（リスト外の概念を作り出さない） |
| `definition` | その概念を「理解している」とはどういう状態かの記述 |
| `prerequisites` | 前提概念の概念IDの配列。体系全体でDAG（循環参照0件） |
| `evidence_patterns`（証跡パターン） | その概念が不足しているときに解答へ現れる「症状」の記述。AIが(a)(b)を判定する材料。**文言が曖昧・汎用的だと概念同士の切り分けが効かなくなる**（M2・M3で繰り返し確認された） |
| `misconceptions` | その概念に関する典型的誤解。(d)内省質問を作る手がかり |

### 3.3 AIの出力

| 用語 | 定義 |
| --- | --- |
| 不足概念 | 学習者の解答過程から推定された「理解が不足していると考えられる概念」。**間違えた問題そのものではなく、その背後にある概念**を指す |
| (a) 不足概念候補 | 概念IDリスト内の `id`/`name` の配列 |
| (b) 根拠 | その判断を支える箇所。解答・自己説明文中の該当箇所を具体的に引用・特定する |
| (c) 確信度 | `high`／`medium`／`low`。根拠が弱い、または複数概念の可能性が拮抗する場合は `low` とし、無理に1つへ絞らない |
| (d) 内省質問 | 学習者に返す問い。正解や結論を教えず、学習者自身が気づけるようにする |
| パイプライン | 入力 → プロンプト（概念IDリストを含む）→ (a)〜(d)のJSON出力、という一連の処理 |
| 概念マップ | 概念IDとその前提関係をグラフとして描き、不足概念・根拠・確信度・内省質問を重ねて示す可視化（M4で実装） |

### 3.4 検証

| 用語 | 定義 |
| --- | --- |
| 疑似データケース | 検証用に筆者が自作した学習者の解答過程。4つのケース設計パターン（①誤答＋明確な自己説明 ②誤答＋曖昧な自己説明 ③正答だが根拠薄弱 ④複数概念にまたがる誤答）で構成 |
| 想定ラベル | 疑似データケース作成時に筆者が付けた「正解とみなす不足概念ID」 |
| 一致率 | 人の判定（M3は想定ラベル、M5は筆者の独立判定）とAI出力(a)が一致した割合。達成基準は70%以上 |
| 根拠妥当性 | (b)が解答・自己説明文中の該当箇所を正しく指し示している割合。達成基準は70%以上 |
| 保留 | ケース設計側の問題で検証に使えないと判断し、一致率の分母から除外すること（例：ケース5） |
| フォーマットエラー率 | 出力が指定JSONスキーマでパースできなかった割合。達成基準は0% |
| M1〜M5 | マイルストーン。M1概念ID体系の構築／M2プロンプトの完成／M3疑似データによる頑健性検証／M4概念マップ可視化・フィードバック提示／M5実データによる妥当性検証 |

## 4. 紛らわしい用語の使い分け

同じ語が複数の意味を持つため、以下のとおり書き分ける。

| 語 | 本研究での意味（この意味で使う） | 混同しやすい別の意味 | 書き分け |
| --- | --- | --- | --- |
| 概念 | 概念ID体系の1項目 | 数学の概念一般 | 数学の内容そのものを指すときは「数学的概念」と明示する |
| 根拠 | AI出力(b)。解答中のどこが判断を支えるか | 研究の主張を支える証拠 | 後者は「妥当性の根拠」と書く |
| 評価 | — （単独では使わない） | 学習者が自分を測る／研究者がAI出力を測る | 前者は「自己評価」、後者は「検証」「判定」と書く |
| 一致率 | 人の判定とAI出力(a)の一致割合 | M3とM5で比較対象が異なる | 必ず「想定ラベルとの一致率（M3）」「筆者判定との一致率（M5）」と対象を添える |
| パターン | — （単独では使わない） | 概念IDの属性／疑似データの類型 | 前者は「evidence_patterns（証跡パターン）」、後者は「ケース設計パターン」と書く |
| 理解度 | 学習者の内的状態（直接は観測できない） | AIの出力／自己評価の値 | AIが出すのは「不足概念の推定」であり理解度そのものではない。自己評価の値は「できる度」と書く |
| 妥当性 | — （単独では使わない） | (b)が正しい箇所を指すか／AI推定が実際の理解度を反映するか | 前者は「根拠妥当性（M3の指標）」、後者は「妥当性検証（M5）」と書く |
| 確信度 | AI出力(c)の `high`/`medium`/`low` | 研究者側の確からしさ | 研究者側には使わない |
| 自己説明 | 入力データの1項目（学習者が書いた文） | 学習方略としての self-explanation | 入力データを指すときは「自己説明文」と書くと曖昧さが減る |
